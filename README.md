# 分隔文本严格解析（从 0 实现）

起始环境只有这份说明、`samples/**` 与 `.gitignore`，没有代码可抄。要新写仓库根入口 `main.py`（Python 3.13 标准库，无第三方依赖、
无构建步骤）：按下面的口径逐字符解析分隔文本，产出逐条记录、错误清单与一份自包含 HTML 报告；解析状态机必须自己写，不许调用 `csv` 模块。

## 一、范围

要做：解析分隔文本；严格 / 容错两种模式；错误条数上限；每处错误给出物理行号、列号与固定原因；把记录与错误清单写成可逐字节核对的文本；
把每份文件的统计与错误汇总成单文件 HTML 报告；汇总行打到 stdout。

不做：不认 UTF-8 以外的编码；不认反斜杠转义与单引号，`\` 只是普通字符；不推断列名、不校验各行列数是否一致、不做类型转换、不做去重；
不修数据（只报错，绝不改写输入）；不联网、不读时钟与随机数；不加构建步骤、不引第三方依赖。

## 二、口径与公式

### 2.1 字节、编码与行尾

- 输入按字节分块读入（块 ≤ 4 MiB），UTF-8 严格解码。
- 开头允许一个 UTF-8 编码头 `EF BB BF`：剥掉，且不计入行列编号。开头是 `FF FE 00 00`、`00 00 FE FF`、`FF FE`、`FE FF` 时判为
  不支持的编码头，记一条 `E_ENCODING_BOM`（行 1 列 1）且不再解析该文件，容错模式也照此处理。
- 其它非法 UTF-8 序列记 `E_UTF8`，位置是该序列起点所在的行与列（列 = 该行已成功解码的字符数 + 1）。
- 行终止符是 LF 或 CRLF，同一文件可混用，行号按 LF 从 1 起递增。`CR` 后面不是 `LF` 就是裸回车，记 `E_BARE_CR`（位置是该 `CR`），
  引号字段内也不放宽。
- 引号字段里的换行是数据：LF 与 CRLF 都归一成单个 `\n` 写进字段值。空行（没有任何字符、只有行终止符）跳过，不算记录也不报错；
  文件末尾没有行终止符时最后一条记录照常成立。

### 2.2 字段与引号

分隔符是 `,`，字段两侧的空白照字面保留（不 trim）。字段只有两种写法：

- 裸字段：不能出现 `"`，出现就记 `E_QUOTE_MID_FIELD`（位置是该引号）。
- 引号字段：字段第一个字符是 `"`；读到下一个 `"` 时看后继——是 `"` 就把一个字面引号写进值并继续；是 `,`、行终止符或文件末尾就结束
  该字段；是别的字符就记 `E_CHAR_AFTER_QUOTE`（位置是那个多余字符）。引号字段里可以有 `,` 和换行。

一条记录的字段数 = 逗号切分后的字段数，至少 1 个（`""` 是 1 个空字段，`,,` 是 3 个空字段）；字段值可为空，长度不设限。

### 2.3 记录、位置与统计

记录号在每份文件内从 1 起连续编号，只数成功解析出来的记录。起始行 = 记录第一个字符所在物理行；结束行 = 该记录的行终止符所在行
（文件末尾没有终止符时取最后一行）。列号按字符（码点）从 1 起、以物理行为基准，引号字段里的换行会换行，列号从 1 重来。
统计三项：记录数、字段总数（成功记录的字段数之和）、错误数。

### 2.4 错误清单、容错与上限

| 代码 | 原因（原样写进错误清单） | 位置 |
| --- | --- | --- |
| `E_ENCODING_BOM` | 不支持的编码头 | 行 1 列 1 |
| `E_UTF8` | 非法 UTF-8 字节 | 非法序列起点 |
| `E_BARE_CR` | 出现裸回车 | 该 `CR` |
| `E_QUOTE_MID_FIELD` | 裸字段中出现引号 | 该引号 |
| `E_CHAR_AFTER_QUOTE` | 引号字段闭合后出现多余字符 | 多余字符 |
| `E_QUOTE_UNCLOSED` | 引号字段未闭合 | 起始引号 |
| `E_LIMIT` | 错误数达到上限 | 触发上限的那条错误的位置 |

严格模式（默认）：第一条错误记下后停止解析该文件，错误清单只有这一条。容错模式（`--tolerant`）：丢掉出错的那条记录，从出错位置之后的
下一个物理行行首继续（引号状态清零、列号从 1 重来）；出错位置之后再没有换行就到文件末尾收尾。单文件最多记 `--max-errors` 条具体错误
（默认 100，取值 1–1000，严格模式下该参数无意义），再出错时改记一条 `E_LIMIT` 并停止解析该文件。

文件状态：`ok` = 到文件末尾且 0 错误；`partial` = 到了末尾但有跳过的记录；`failed` = 没到末尾（严格模式遇到错误、容错模式达到上限、
编码头不支持）。

## 三、状态机与数据结构

解析按字符推进，只有五个状态：字段开始（文件开头、行首或刚吃过 `,`）→ 裸字段 / 引号字段 → 引号刚闭合（只接受 `,`、行终止符、
文件末尾）→ 记录结束（写出一条记录，回到字段开始）。行终止符只在非引号状态下结束记录；引号字段里的换行只涨行号，不参与字段边界。

每条记录用「起始行、结束行、字段值列表」描述，每处错误用「行号、列号、代码」描述，原因由代码查表得到。两份文本产物按这些结构顺序渲染，
报告用同一批数字。

## 四、输入输出与文件格式

    python3 main.py <输入文件>... [--out 目录] [--report 页面.html] [--tolerant] [--max-errors N]

默认 `--out var/out`、`--report var/report.html`，目录不存在就创建。每份输入产出两个文件，名字是输入文件名去掉最后一个扩展名：

- `<名>.records.txt`：一条记录一行，制表符分隔，依次是记录号、起始行、结束行、字段数、各字段值。字段值里的 `\`、制表符、换行、
  回车分别写成 `\\`、`\t`、`\n`、`\r` 两个字符，其余原样；输出行不加引号。
- `<名>.errors.txt`：一行一条错误，制表符分隔，依次是行号、列号、代码、原因。

两个文件都 UTF-8 无 BOM、只用 LF、末行带换行；没有内容时是 0 字节空文件。stdout 每份输入一行（制表符分隔）：名字、状态、记录数、
字段总数、错误数，顺序同命令行；别的信息走 stderr。退出码：0 = 全部 `ok`；1 = 有 `partial` 或 `failed`；2 = 用法或读写错误。

报告是 `--report` 指定的单文件 HTML（UTF-8 无 BOM、LF、末行带换行）：只用内联 `<style>`，不引外链、不写绝对路径、不用 `<script>`、
不联网。`<h1>` 后是汇总表 `<table id="summary">`（表头：文件、状态、记录数、字段总数、错误数；每份输入一行，顺序同命令行）；
再往后每份输入一节 `<section class="file" data-file="<文件名>" data-status="ok|partial|failed">`，节内有文件名与状态中文
（通过 / 部分通过 / 失败）、`<p class="stats" data-records data-fields data-errors>` 与错误表 `<table class="errors">`
（表头：行、列、代码、原因）。报告里的数字必须与两个文本文件一致。

## 五、性能与验收口径

预算（Python 3.13，WSL2 + SSD，单进程，含启动时间）：单文件 ≤ 256 MiB、单次输入 ≤ 64 个文件；64 MiB 规范文件（约 200 万条记录、
每行 ~32 字节、无引号）端到端 ≤ 20 s（吞吐 ≥ 3.2 MiB/s）；峰值常驻内存 ≤ 128 MiB，不许整文件读入内存。

验收：

1. 按第六节命令逐份跑样例，`--out` 下的 `<名>.records.txt`、`<名>.errors.txt` 与期望文件逐字节相同（顺序敏感）。
2. stdout 汇总行与报告的数字同两个文本文件一致，报告结构符合第四节。
3. 同一输入跑两遍产物逐字节相同；不依赖时钟、随机数、哈希顺序、绝对路径与环境变量；不写回输入文件。
4. 用未入库的 64 MiB 同风格文件复核吞吐与内存。
5. 复核会用未公开的同风格文件；不得读取 `samples/expected/**`，不得按文件名、路径或内容写死结果，不得改动 `samples/**`。

## 六、样例说明

`samples/files/<名>.txt` 是输入，`samples/expected/<名>.<模式>.records.txt` 与 `<名>.<模式>.errors.txt` 是期望结果，`<模式>` 取
`strict` 或 `tolerant`。严格模式：

    python3 main.py samples/files/<名>.txt --out var/out --report var/report.html

容错模式给同一条命令加 `--tolerant`；`09-error-limit` 还要加 `--max-errors 3`。

| 样例 | 覆盖 | 两种模式的看点 |
| --- | --- | --- |
| `01-basic` | 规范文件：LF、空字段、中间空行、末行无换行 | 都是 `ok`，记录相同 |
| `02-doubled-quotes` | 双写引号、引号里的逗号、空引号字段、值里的制表符与反斜杠 | 都是 `ok`，字段值按第四节转义 |
| `03-quoted-newline` | 引号里含分隔符与换行、同一文件 LF/CRLF 混用 | 跨行记录的两端行号与值里的 `\n` |
| `04-stray-quote` | 字段中间冒出来的引号（行中、行尾各一处） | 严格停在第 3 行；容错跳过两条坏记录 |
| `05-unclosed-quote` | 漏收尾引号，后两行被吞进同一条记录 | 都在第 4 行报错，只有状态不同 |
| `06-mixed-eol` | LF 与 CRLF 混用、行中间夹一个裸 CR | 严格在第 4 行停；容错跳过该行 |
| `07-bom-utf8` | UTF-8 编码头、第 1 行的引号错误 | 容错跳过第 1 条记录；列号 6 说明 BOM 不入列 |
| `08-bom-utf16` | UTF-16LE 编码头 | 两种模式都 `failed`，records 为空 |
| `09-error-limit` | 一处接一处的引号错误 | 严格停在第 3 行；容错记满 3 条后追加 `E_LIMIT` |

`samples/notes.md` 是现场记录，不参与判定。
